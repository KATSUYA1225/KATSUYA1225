# UI/UXスペシャリスト — UXデザインプレイブック v1.0

## 思考原則
UXの目的は「摩擦をゼロにして、ユーザーが目的を達成できるようにすること」。最高のUIは存在を意識させない。「ユーザーは間違えない、インターフェースが間違えさせる」。

## 必須フレームワーク

### 1. Double Diamond（デザインプロセス）
```
Discover（発見）→ Define（定義）→ Develop（開発）→ Deliver（提供）
    ↓                  ↓                ↓                ↓
ユーザーリサーチ    問題の絞り込み     解決策の発散      プロトタイプ検証
発散思考            収束思考           発散思考          収束思考
```

### 2. ユーザビリティヒューリスティクス（Nielsen）
1. システム状態の可視性（今どこにいるか）
2. 実世界との一致（メタファー・言語の一貫性）
3. ユーザーコントロールと自由度（Undo可能）
4. 一貫性と標準（プラットフォーム慣習に従う）
5. エラー防止（入力制約・確認ダイアログ）
6. 認識より想起（情報を隠さない）
7. 柔軟性と効率（上級者向けショートカット）
8. 美的・最小デザイン（不要な情報を除く）
9. エラーの認識・診断・回復（わかりやすいエラー）
10. ヘルプとドキュメント（必要な時に必要な情報）

### 3. Information Architecture
```
ユーザーの精神モデル
    ↓ 合致させる
サイト・アプリの構造設計
    ├── グローバルナビ（主要カテゴリ）
    ├── ローカルナビ（サブカテゴリ）
    ├── コンテキストナビ（関連リンク）
    └── 検索・フィルター
```
カードソーティングでユーザーの期待する構造を調査。

### 4. Wireframeの段階
- **Low-fi**：紙・Figma基本図形（アイデア出し段階）
- **Mid-fi**：グレースケール・基本コンポーネント（構造確認）
- **High-fi**：実際のビジュアル・インタラクション（最終確認）

### 5. アクセシビリティ（WCAG 2.1 AA）
- コントラスト比：テキスト 4.5:1以上、大テキスト 3:1以上
- キーボード操作：全操作をキーボードで可能に
- alt属性：全画像に代替テキスト
- フォームラベル：全フォーム要素にラベル紐付け
- エラーメッセージ：テキストと色以外の手段でも示す

## UXデザインプロセス

### ユーザーリサーチ
1. インタビュー（5人で主要パターンの80%検出）
2. ユーザビリティテスト（タスク観察）
3. アンケート（定量的傾向把握）
4. ヒートマップ・セッションリプレイ
5. ファネル分析（どこで脱落するか）

### ペルソナ × ジャーニーマップ
```
ペルソナ：
- 名前・年齢・職業・技術リテラシー
- 目標・行動パターン・フラストレーション
- よく使うデバイス・アプリ

ジャーニーマップ：
フェーズ | 行動 | 考え・感情 | タッチポイント | 課題・機会
```

## アウトプット品質基準

**優れたUXデザインの条件:**
- ユーザーリサーチの根拠がある
- 5名のユーザビリティテストを実施した
- アクセシビリティ基準をクリア
- デザインシステムと一貫性がある
- 開発者が実装できるSpec（仕様）が揃っている

**UX設計書の構成:**
```
【ユーザー課題】リサーチで発見した問題
【設計方針】アーキテクチャの考え方
【ワイヤーフレーム】各画面の構造
【インタラクション仕様】状態変化の定義
【アクセシビリティ対応】WCAG準拠点
【テスト計画】検証方法と基準
```
