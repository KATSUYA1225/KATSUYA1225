# データ分析 — アナリティクスプレイブック v1.0

## 思考原則
「データは過去を映す鏡、分析は未来への羅針盤」。相関と因果を混同しない。仮説→検証→意思決定のサイクルを高速で回す。

## 必須フレームワーク

### 1. North Star Metric
ビジネスの核心的な価値を示す1つの指標。
- Airbnb：宿泊泊数
- Spotify：1ヶ月あたりの聴取時間
- Slack：組織内のメッセージ送信数
→ NSMの改善施策にリソース集中することで成長加速

### 2. CRISP-DM（分析プロセス）
1. Business Understanding：ビジネス課題の明確化
2. Data Understanding：データ探索・品質確認
3. Data Preparation：前処理・特徴量エンジニアリング
4. Modeling：手法選択・学習・評価
5. Evaluation：ビジネス目標との整合性確認
6. Deployment：実装・モニタリング

### 3. A/Bテスト設計
```
仮説：[変数X]を変えると[指標Y]が[方向Z]に変化する
理由：[根拠]
成功基準：[KPI]が統計的有意（p<0.05）に[X%]以上改善
サンプルサイズ：検出力80%、有意水準5%で[N]サンプル必要
テスト期間：最低[N]週間（週次サイクルの影響を平滑化）
```

### 4. コホート分析
| コホート | 1週 | 2週 | 4週 | 8週 | 12週 |
|---------|-----|-----|-----|-----|------|
| 1月獲得 | 100% | 45% | 30% | 22% | 18% |
| 2月獲得 | 100% | 48% | 33% | 25% | - |
→ リテンション改善の効果をコホートで測定

### 5. ファネル分析
各ステップの転換率を測定し、最大ドロップポイントを特定。
```
訪問者 100% → 登録 25% → 初回アクション 15% → 7日継続 8% → 課金 3%
                                          ↑
                               ここが最大ドロップ → 集中改善
```

### 6. RFM分析（顧客セグメント）
| 指標 | 意味 |
|------|------|
| Recency | 最終購買からの日数（低いほど良い） |
| Frequency | 購買回数（高いほど良い） |
| Monetary | 累計購買金額（高いほど良い） |
→ 5段階評価×3指標で125セグメント、主要10パターンへ集約

## 分析実行プロセス

### 問題発見
1. ビジネス目標の確認（何を改善したいか）
2. 現状の数値把握（ベースライン）
3. 外れ値・異常値の特定
4. 比較分析（前期比・競合比・計画比）

### 仮説立案
1. なぜ問題が起きているか（5 Why）
2. 改善できる変数は何か
3. 効果が最大の施策は何か（ICE Score）

### 可視化の原則
- 1枚のグラフに1つのメッセージ
- タイトルは「発見」を表す（「売上推移」×→「Q3売上は前年比20%増加」◎）
- 比較対象を必ず設ける
- カラーは最大3色（アクセント1色）

## アウトプット品質基準

**優れな分析レポートの条件:**
- 「So what?」が明確（数字の羅列ではなく示唆）
- 統計的有意性が確認されている
- ビジネスへのインパクトが定量化されている
- 推奨アクションが具体的
- 分析の限界（バイアス・データ欠損）が明示

**分析レポートの構成:**
```
【発見（1行サマリー）】最も重要な発見を1文で
【背景・目的】何を解明しようとしたか
【分析アプローチ】方法論と前提条件
【主要発見】グラフ＋解釈（3〜5点）
【推奨アクション】優先順位付き施策リスト
【次の分析課題】さらに深堀すべき点
```

## よくある分析の失敗
- 相関を因果と誤解する（アイスクリーム売上と溺死者数の相関）
- サバイバーシップバイアス：成功例だけを見て法則化
- p-hacking：有意になるまでデータを分割・追加
- 分析のための分析：意思決定に繋がらない
